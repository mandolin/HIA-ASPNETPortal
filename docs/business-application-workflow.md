# 业务申请：从提交到办结

一条申请交出去之后，你关心的是三件事：它有没有真的提交、现在到哪一步了、下一步该谁动。这页按这个顺序说。

## 开始之前

- 你已登录门户。模块按当前用户取一次用户记录，取不到就按无权限处理，不会显示别人的数据。
- 「业务申请」要挂在某个页签上才会出现。找不到这个页签，说明部署方没把它放出来，找管理员确认。
- 这一页写的是**通用申请骨架**：标题、类别、摘要、正文。具体业务字段（科研、井设计、情报等）由各自的专用模块承载，不要在这里找。

## 提交一条申请

1. 打开承载该模块的页签，在表单里填**标题**。
2. 在**类别**下拉框里选一个类别。
3. 填**摘要**和**正文**。
4. 点**提交**。

提交成功后，表单下方的列表里出现这条申请，同时写入一条时间线事件；审计里也留下"谁在什么时候提交了哪条申请"。

## 提交之后

状态从 `Submitted`（已提交）开始，进入待审核窗口，之后可能变成：

| 变成 | 谁动的 | 你要做什么 |
| --- | --- | --- |
| 已批准 | 审核方 | 办结 |
| 已退回 | 审核方 | 你补充后重新提交 |
| 已驳回 | 审核方 | 终态，不用再管 |
| 已关闭 | 审核方 | 终态，不用再管 |

你在页面上能看到的只有**自己提交过的**申请 —— 列表按当前用户过滤，没有"查看全部申请"的入口。

## 被退回之后

退回（`Returned`）之后，改完内容重新提交（`Resubmit`）就回到 `Submitted`。这一步是**申请人自助**路径，不走审核。

有两个动作是定义了但**没有接线**的：「撤回」（`Withdraw`）和「认领」（`Claim`）。当前实现里没有任何界面或流程会触发它们，所以提交之后并不能撤回。

## 看不到审批过程

这一节最容易误解，说清楚三件事：

- **没有审批轨迹页面**。审批流转是数据层的状态机，记在系统里；界面上看不到"谁在什么时候批的"这样的时间线。
- **「我的待办」只呈现、不办理**。那里能列出未完成的待办，每条标出来源模块，但它不审批、不改数据、也不回写来源模块。
- 想推进一条申请，回到产生它的那个模块去。

## 没提交成功的时候

- **必填是在提交之后才判的**。这个表单上没有红色必填提示（标记层一个必填校验器都没有），空标题或空正文会在你点提交后被服务端拒掉。
- **正文超过 4000 字会被截断**，不是报错；标题 200 字、摘要 500 字同理。
- **提交后列表里没出现新条目**，先确认提交是否真的成功 —— 被拒时不会有新条目，列表也不会报错。
