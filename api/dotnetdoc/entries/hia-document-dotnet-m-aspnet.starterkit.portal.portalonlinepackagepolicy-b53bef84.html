public static bool ASPNET.StarterKit.Portal.PortalOnlinePackagePolicy.TryValidateDecompressedBudget(System.Collections.Generic.IList<long> declaredLengths, out string reason)

按 ZIP 条目声明长度在解压前校验条目数、单条目上限与解压后累计上限（zip bomb 防护）。

Validates entry count, per-entry cap, and cumulative decompressed size from declared ZIP entry lengths before extraction (zip-bomb defence).

Localized Fields

remarks

Microsoft Learn 明确指出 ZipArchive 与 ExtractToDirectory 都不限制解压后总大小与条目数，必须由调用方自行强制； .NET Framework 4.8 不会在读取时自动校验 CRC-32，故本方法只依据声明长度做「上界预算」，完整性另由签名/哈希校验承担。

Microsoft Learn states that neither ZipArchive nor ExtractToDirectory limits total decompressed size or entry count, so callers must enforce both; .NET Framework 4.8 does not auto-validate CRC-32 while reading, so this method only budgets an upper bound from declared lengths and integrity belongs to separate signature/hash checks.

params.declaredLengths.summary

每个条目的声明解压字节数序列，不能为 null。

Sequence of declared decompressed byte counts, one per entry; cannot be null.

params.reason.summary

拒绝原因的稳定短语。

Stable rejection phrase.

returns.summary

全部体积约束满足时为 true。

True when all size constraints are satisfied.
