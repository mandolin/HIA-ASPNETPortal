public ASPNET.StarterKit.Portal.CollaborationItemDataScope.CollaborationItemDataScope(int actorUserId, bool isAdministrator, bool isParticipant, System.Collections.Generic.IEnumerable<int> visibleOrganizationUnitIds, bool holdsOwnerRoleKey = false)

用服务端已解析的归属、参与和组织证据创建数据范围快照。

Creates a data-scope snapshot from server-resolved ownership, participation, and organization evidence.

Localized Fields

params.actorUserId.summary

服务端重新解析得到的门户用户标识；非正值表示身份缺失，判定会直接拒绝。

Portal-user identifier re-resolved by the server; a non-positive value means the identity is missing and the decision denies directly.

params.isAdministrator.summary

服务端按角色或协同管理员权限计算出的管理员标记；该标记只延续既有集中查看能力，仍受上游权限门禁约束。

Administrator flag computed by the server from roles or the collaboration-admin permission; it only continues the existing centralized viewing capability and remains constrained by the upstream permission gate.

params.isParticipant.summary

当前用户是否属于事项参与人集合（协办或关注）；由调用方在服务端查询后传入。

Whether the current user belongs to the item participant set (Collaborator or Watcher); supplied by the caller after a server-side query.

params.visibleOrganizationUnitIds.summary

当前用户可见组织单元标识集合；可为空引用，空集合按"范围未知"处理。

Organization-unit identifiers visible to the current user; may be null, and an empty collection is treated as "scope unknown".

params.holdsOwnerRoleKey.summary

当前用户是否持有该事项的负责人角色键（受控权限键），由服务端比较后传入；策略本身不接触权限集合。W72 新增，用于让读取边界与既有写资格对齐。

Whether the current user holds the item's owner role key (a controlled permission key), supplied after a server-side comparison; the policy itself never touches a permission collection. Added in W72 so the read boundary aligns with the existing write eligibility.
