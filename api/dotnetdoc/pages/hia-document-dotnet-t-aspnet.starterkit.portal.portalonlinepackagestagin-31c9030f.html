class ASPNET.StarterKit.Portal.PortalOnlinePackageStaging

在线能力包的隔离暂存器：把一个已通过策略校验的 ZIP 包解压到「全新的、应用自控的」隔离子目录，失败时整体清理。

Isolated staging for an online capability package: extracts one policy-validated ZIP into a fresh, application-controlled subdirectory and removes it entirely on failure.

remarks

本类型是 `[已脱敏]` 的承载基座，只做「上传字节 → 隔离目录」这一段，不做安装、不写数据库、不写审计、不改装配态、不加载任何程序集或脚本。 实现严格遵循 Microsoft Learn「Best practices for working with ZIP and TAR archives in .NET」：不受信任输入不得使用 ZipFile.ExtractToDirectory（其路径校验只是 best-effort）； 必须手工迭代条目、用 Path.GetFullPath 解析后以带尾部分隔符的 StartsWith 断言边界、强制解压后大小与条目数上限、使用全新受控目标目录、且 overwrite:false。 本类面向 .NET Framework 4.8：使用 Path.Combine 而非 Path.Join（后者为 .NET Core 2.1+），不依赖 TAR、异步解压、加密 ZIP 或运行时 CRC-32 自动校验。

This type is the `[已脱敏]` hosting base and covers only the "uploaded bytes to isolated directory" segment: it performs no installation, database write, audit write, assembly-state change, or loading of assemblies or scripts. It follows Microsoft Learn "Best practices for working with ZIP and TAR archives in .NET": untrusted input must not use ZipFile.ExtractToDirectory (its path validation is best-effort only); entries must be iterated manually, resolved with Path.GetFullPath and asserted with a trailing-separator StartsWith check, bounded by decompressed size and entry-count limits, extracted into a fresh controlled directory, and always with overwrite:false. It targets .NET Framework 4.8: Path.Combine is used instead of Path.Join (.NET Core 2.1+ only), and there is no dependency on TAR, async extraction, encrypted ZIP, or runtime CRC-32 validation.
