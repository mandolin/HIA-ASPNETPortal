PortalNavigationGroupAlias

dotnet-type.NET
class ASPNET.StarterKit.Portal.PortalNavigationGroupAlias

主导航「分组配置别名」的封闭词表。分组只描述展示顺序与折叠归属，不描述父子表结构、不参与授权判定； 页签可见性仍由 `PortalCfg_Tabs.AccessRoles` 与既有的 Tab gate 逐项判定（A 级硬边界）。

Closed vocabulary of main-navigation group configuration aliases. A group describes only presentation order and collapse membership; it describes no parent/child table structure and takes no part in authorization. Tab visibility is still decided per tab by `PortalCfg_Tabs.AccessRoles` and the existing tab gate (class-A boundary).

remarks

设计依据（`[已脱敏]` Q1 裁定 ③）：R4 的「两级菜单」以配置别名分组达成，不改 `PortalCfg_Tabs` 表结构、 不加父子列、不做深度/环检测；分组名沿用 `PortalNavigationEntry.GetDisplayName(CultureInfo)` 的中英列范式做本地化， 不引入新的 .resx 键。部署侧可用 `Portal.Navigation.GroupAliases` 配置键覆盖个别页签的分组归属； 配置非法时 fail-closed 回退到本词表，**不隐藏任何页签**（降级为一级平铺）。

Rationale (`[已脱敏]` Q1 ruling ③): R4's two-level menu is achieved through configuration aliases without changing the `PortalCfg_Tabs` schema, adding a parent column, or introducing depth/cycle checks. Group labels are localized through the same Chinese/English column convention as `PortalNavigationEntry.GetDisplayName(CultureInfo)`; no new .resx keys are introduced. Deployments may override a tab's group with the `Portal.Navigation.GroupAliases` setting; invalid configuration fails closed back to this vocabulary and never hides a tab (degrade to flat navigation).
