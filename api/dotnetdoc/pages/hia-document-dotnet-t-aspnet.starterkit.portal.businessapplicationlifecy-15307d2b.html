BusinessApplicationLifecycle

dotnet-type.NET
class ASPNET.StarterKit.Portal.BusinessApplicationLifecycle

通用业务申请审批生命周期门面：在已有的单一事实源（PortalBusinessApplicationStatuses / PortalWorkflowActions / PortalBusinessApplicationTransitions）之上，吸收各 BasicBusiness 模块的历史状态词汇，提供「归一化 → 校验 → 判定」的统一入口，消除 Expense/Leave 等模块重复实现的状态常量、Resubmit 方法与本地化孪生方法（[已脱敏] Q1–Q6 裁定）。

Unified business-application approval-lifecycle facade. On top of the existing single source of truth (PortalBusinessApplicationStatuses / PortalWorkflowActions / PortalBusinessApplicationTransitions), it absorbs each BasicBusiness module's legacy status vocabulary and exposes one "normalize → validate → decide" entry point, removing the duplicated status constants, resubmit methods and localized twin methods that Expense/Leave etc. reimplemented ([已脱敏] Q1–Q6 ruling).

remarks

本类不重造状态机：迁移判定全部委托 PortalBusinessApplicationTransitions（其 Resubmit 已是 Returned→Submitted 且不在后台审核谓词内，与 Q2「Returned 可重提、Rejected 终态」一致）。本类只补齐「历史模块词汇 → 规范词」的归一化与便捷判定；LocalizeStatus 因依赖 App_GlobalResources 留在 Web 层（PortalStatusLocalizer）调用本类。归一化层实现 Q1「统一词汇」而不改写存储字符串，保留既有数据兼容性。

This class does not reinvent the state machine: all transition checks delegate to PortalBusinessApplicationTransitions (whose Resubmit is already Returned→Submitted and excluded from the review predicate, matching Q2 "Returned resubmittable, Rejected terminal"). This class only adds legacy-vocabulary normalization and convenience decisions; LocalizeStatus stays in the web layer (PortalStatusLocalizer) because it depends on App_GlobalResources. The normalization layer realizes Q1 "unified vocabulary" without rewriting stored strings, preserving existing data-store compatibility.
