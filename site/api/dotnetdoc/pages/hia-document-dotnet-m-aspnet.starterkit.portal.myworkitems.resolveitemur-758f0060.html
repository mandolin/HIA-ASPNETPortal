ResolveItemUrl

dotnet-method.NET
ASPNET.StarterKit.Portal.MyWorkItems.ResolveItemUrl(ASPNET.StarterKit.Portal.PortalWorkItemInfo) /* return type unavailable */

解析待办对应业务对象的前台可达地址；解析落空或当前用户无权访问承载页签时返回空串，由标记层改为降级提示。

Resolves the front-end reachable URL of the business object behind a work item; when resolution falls through or the current user may not access the hosting tab it returns an empty string and the markup shows the degraded hint instead.

remarks

P77.3 取代原 T3 判定（2026-09-29 的「三类业务在前台恒不可达、故恒返回空串」）。原判定只看到「没有可静态解析的前台深链」，**漏掉了运行期反查**：模块实例归属的页签本就登记在库中，可按「业务类型 → 能力键 → 主责模块包 → 已验证桌面入口 → 模块定义 → 模块实例 → 承载页签」逐环反查，再用当次请求的角色检查确认可达性（见）。命中即产出地址，任一环落空即降级为提示；后台的 Admin 映射与这里的普通用户可达性判定互不替代。 Admin/WorkItems.aspx

P77.3 supersedes the original T3 verdict (2026-09-29: every kind is unreachable in the front end, so always return an empty string). That verdict saw only that no statically resolvable front-end deep link exists and **missed the runtime reverse lookup**: the tab owning a module instance is already registered in the database, so the chain from business kind to capability key to primary module package to validated desktop entry to module definition to module instance to hosting tab can be walked, and the current request's role check then confirms reachability (see). A full pass yields a URL while any failed link degrades to the hint. The Admin mapping onand this ordinary-user reachability decision do not substitute for each other. Admin/WorkItems.aspx
