在线能力包的完整性与签名校验（纯函数，不读取配置、不连接数据库、不执行安装）。 承担 `.NET Framework 4.8` 不会在读取 ZIP 时自动校验 CRC-32 所缺的完整性职责： 由 SHA-256 内容摘要与独立 RSA-SHA256 签名提供，而不是依赖运行时 CRC 或包内声明。

Integrity and signature verification for online capability packages (pure functions; no config read, no database connection, no installation). It carries the integrity responsibility missing because `.NET Framework 4.8` does not auto-validate ZIP CRC-32 while reading: a SHA-256 content digest and a separate RSA-SHA256 signature provide it, rather than runtime CRC or package-declared claims.

remarks

哈希口径与离线工具 `Invoke-PortalModuleAssemblyCheck.ps1` 的 `Get-FileSha256` **逐字一致**： SHA256 计算后经 `BitConverter.ToString(...).Replace("-","").ToLowerInvariant()` 得到 64 位小写十六进制。 **A 级硬边界**：期望哈希只能来自服务端隔离暂存时记录的值，公钥只能来自服务端受信任部署配置； 二者**绝不**从包内容、包内 `module.json` 的来源声明或 capability 字段解析，也不因包「自称可信」而放宽。 所有校验 fail-closed：公钥/签名/摘要缺失、格式错、验证失败或异常一律拒绝，不回显不可信文本。

The digest format is **character-for-character identical** to `Get-FileSha256` in the offline tool `Invoke-PortalModuleAssemblyCheck.ps1`: SHA256 followed by `BitConverter.ToString(...).Replace("-","").ToLowerInvariant()`, yielding 64 lowercase hex characters. **A-level hard boundary**: the expected hash comes only from the server-side isolated staging record, and the public key only from trusted server-side deployment configuration; neither is parsed from package content, a `module.json` origin claim, or a capability field, and neither is relaxed because a package "claims to be trusted". Every check fails closed: missing public key, signature, or digest, malformed input, verification failure, or an exception is rejected, and no untrusted text is echoed.
