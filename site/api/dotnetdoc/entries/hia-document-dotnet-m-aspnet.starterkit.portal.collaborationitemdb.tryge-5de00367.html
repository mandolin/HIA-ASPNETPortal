**fail-closed 不变量**：任一前置缺失都判为"未授权"而不是放行 —— 无用户 Id、`usersDb` 不可用、 按 Id 找不到用户、用户名为空，或读取过程中抛异常，一律返回。`rolesDb` 不可用时权限键集合为**空**， 不会因此获得任何权限（管理员标志仍由角色名或显式权限键决定，不因依赖缺失而被提升）。 该约束无法由普通静态检查证明，故显式登记：调用方不得把"取不到授权"当作"有权限"处理。 false

**Fail-closed invariant**: any missing prerequisite is judged "unauthorized" rather than allowed — no user id, an unavailable `usersDb`, no user found by id, an empty user name, or an exception during the read all return. When `rolesDb` is unavailable the permission key set is **empty**, which grants nothing (the administrator flag still depends on a role name or an explicit permission key and is never elevated by a missing dependency). Ordinary static checks cannot prove that constraint, so it is registered here explicitly: callers must never treat "authorization unavailable" as "authorized". false
