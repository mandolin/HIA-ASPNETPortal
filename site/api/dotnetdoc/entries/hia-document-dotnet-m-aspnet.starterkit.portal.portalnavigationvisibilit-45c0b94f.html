判定门户配置中的 Tab 是否被入口 gate 阻断；阻断判定按**导航稳定键**查 registry，缺失时才回退到显示名。

Decides whether a portal-configuration tab is blocked by the entry gate; the registry lookup uses the **navigation stable key**, falling back to the display name only when it is absent.

remarks

本方法刻意采用与动作区相反的失败方向：未登记 Tab、空白名或上下文缺失一律**放行**。原因是主导航在调用本方法前已按角色过滤，放行不会泄露超权入口；反之若 gate 故障导致全部 Tab 消失，会把"治理增强"变成可用性事故。阻断判定本身仍复用统一的六步可见性判定，不另立规则。 这也解释了为什么必须传稳定键：放行兜底很安全，但"因为显示名本地化导致查不到登记项"而放行，等于让一条治理规则无声消失。

This method deliberately fails in the opposite direction from the action area: an unregistered tab, a blank name, or a missing context is always allowed. The main navigation has already been filtered by role before this call, so allowing cannot leak an over-permissioned entry, whereas losing every tab to a gate fault would turn a governance improvement into an availability incident. The blocking decision itself still reuses the shared six-step visibility evaluation rather than defining new rules. This is also why the stable key must be passed: the allow-fallback is safe, but allowing *because a localized display name missed the registry* silently removes a governance rule.
