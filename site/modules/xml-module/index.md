# XML / XSL 模块（XmlModule）

> 模块目录：`src/Portal/DesktopModules/`｜视图：`XmlModule.ascx`｜编辑页：`EditXml.aspx`
> 本页是**详细使用说明**；一句话速查见[用户指南的常见模块一节]({{ site.baseurl }}/user-guide/)。

## 用途与前置

XML / XSL 模块渲染**部署在站内的 XML 数据**，并可选用 XSL/T 转换后呈现。它把"渲染什么"完全交给**受信任部署目录里的文件**，自身不存数据。

前置条件：

1. 你已登录门户，并拥有**该模块的编辑权限**（`HasEditPermissions(moduleId)`，逐请求校验）。**不要求** HTML 模块那种 `ContentRawHtmlEdit` 窄权限。
2. 模块需挂载在页签上。当前部署（开发库实测）：**1 个实例**——首页「热门动态」（`ModuleId=6`，`xmlsrc=~/data/sales.xml`、`xslsrc=~/data/sales.xsl`）。
3. XML 与 XSL 文件必须**事先存在于应用的受信任部署目录内**（例如 `~/Data/`）。**本模块不提供上传、也不提供在线编辑**。

## 操作步骤

**配置数据源与转换**

1. 打开承载 XML 模块的页签，点击模块标题栏的编辑入口。
2. 填写 **XML 数据文件的应用内虚拟路径**（`XmlDataSrc`）——例如 `~/data/sales.xml`。
3. 可选：填写 **XSL/T 转换文件的应用内虚拟路径**（`XslTransformSrc`）——例如 `~/data/sales.xsl`；不填则直接显示 XML 内容。
4. 保存。保存时两个值都经**同一路径策略规范化**，**任一不合规即拒绝保存**（提示 `EditXml_MessageInvalidResourcePath`，**不含原始输入**）。

**运行时发生什么**

- 两个路径**各自**经受信任部署路径规范化与**物理文件存在性校验**后，才交给 `Xml` 控件（`DocumentSource` / `TransformSource`）；**标记层不接受客户端路径或远程资源**。
- 任一路径不合规或文件不存在 → 只显示**中性的编码提示**（`Legacy_XmlModule_MessageXmlUnavailable` / `Legacy_XmlModule_MessageXsltUnavailable`），**不回显原始路径、不输出物理路径或异常堆栈**。
- **只配 XML、不配 XSL 也能正常显示**（两者独立校验）。

## 字段表

| 字段 | 控件 id | 类型 | 长度上限 | 必填 | 校验 |
| --- | --- | --- | --- | --- | --- |
| XML 数据文件路径 | `XmlDataSrc` | 单行文本 | 250 | 可选 | 保存时经路径策略规范化，不合规拒绝保存 |
| XSL/T 转换文件路径 | `XslTransformSrc` | 单行文本 | 250 | 可选 | 保存时经路径策略规范化，不合规拒绝保存 |

控件 id、类型与长度取自 `EditXml.aspx` 的标记，**不是本文档的估计**。

## 必填与校验

- **零必填**：该编辑页**没有任何 `RequiredFieldValidator`**，两个字段都可留空保存。
- **保存期校验不是"格式校验"而是"路径合规校验"**：两个值都经同一路径策略规范化，**任一不合规即拒绝保存**（`EditXml_MessageInvalidResourcePath`）。这与其它模块"填什么存什么"的做法**不同**——本模块在保存时就拦下不合规路径。
- 注意：**留空是允许的**（模块可以只配 XML，或暂时清空），"不合规"与"为空"是两件事。

## 存储与审计

- **存储**：**模块设置**（`ModulesConfig.GetModuleSettings` / `ModulesConfig.UpdateModuleSetting`），落到 `PortalCfg_ModuleSettings`；两个设置键是 `xmlsrc` 与 `xslsrc`。**本模块没有自己的业务数据表**。
- **审计**：**该保存路径不写运营审计**，运营审计表里不会留下谁改过 XML 配置的记录。

## 权限

- 编辑需**正整数 `Mid`** + `HasEditPermissions(moduleId)`；**不要求** `ContentRawHtmlEdit` 窄权限。
- 首次加载只读取当前模块的既有设置，且**在授权通过之后**才读（源码注释明确：先校验、后读设置）。
- 查看渲染结果不需要编辑权限。

## 常见问题

**保存时提示路径不合法**——填的不是应用内虚拟路径（如 `~/data/x.xml` 形式），或指向了站外地址/物理路径。**只接受受信任部署目录内的虚拟路径**。

**页面上出现的是一段中性提示、看不到内容**——运行期校验未通过：文件不存在、路径不合规，或 XSL 缺失。注意提示**不会告诉你原始路径**（这是有意的），需自己核对设置里的路径与实际文件。

**只配了 XML 却显示提示**——XML 文件本身不存在或路径不合规；XSL 是否配置与此无关（两者独立校验）。

**想要一个只配 XML 的效果**——把 `XslTransformSrc` **留空**即可，不需要删除 XSL 文件。

**想上传 XML 或 XSL**——本模块**不提供上传**（源码明确：只保存已部署资源的虚拟路径，不处理文件内容）。请先把文件部署到应用内，再填路径。

**想引用外部站点或远程样式表**——**不支持**：标记层不接受客户端路径或远程资源，模块也不自动加载外部 XML、远程样式表或脚本。

## 边界与不做

- 本模块**不做**上传、**不做**在线编辑、**不做**外部 URL 或任意物理路径、**不做**自动加载外部 XML/远程样式表/脚本、**不做**内容编辑（只指路径）、**不做**操作审计。
- 本模块**不写运营审计**（见上节）。
- 运行时**不回显原始路径、不输出物理路径或异常堆栈**——排查时请从设置侧核对，而不是期待页面给出细节。
- 本页覆盖**编辑侧的完整字段与校验**；**不依赖运行期截图**——所有结论可回溯到源码标记与已核实的部署读数。
- 部署实例数（1 个）与其 `xmlsrc` / `xslsrc` 取值是交付时的快照；**新增或迁移页签后需重新核对**本节。
- 与[图片模块]({{ site.baseurl }}/modules/image-module/)相比，两者都把配置存进**模块设置**而非自有表；差别在于本模块的设置是**受信任部署资源的虚拟路径**并带**保存期路径合规校验与运行期降级**，而图片模块的设置是纯文本地址与尺寸、无任何校验。
