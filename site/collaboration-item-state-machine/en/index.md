# Collaboration item state machine

> Code source of truth:
> `src/Portal.Components/PortalCollaborationItemTransitions.cs`.

## 1. Status vocabulary

| Status (constant) | Meaning |
| --- | --- |
| `Draft` | Draft; not yet submitted to a handler |
| `Submitted` | Submitted; awaiting an owner or handling role |
| `InProgress` | Being handled |
| `Returned` | Returned to the initiator for additions |
| `Completed` | Completed (terminal) |
| `Rejected` | Rejected (terminal) |
| `Cancelled` | Cancelled (terminal) |
| `Closed` | Closed / archived (terminal) |

The status set is guaranteed jointly by `PortalCollaborationItemStatuses` and the database constraint
`CK_PortalBiz_CollaborationItems_Status` (the two must agree). The terminal states are `Completed` / `Rejected` /
`Cancelled` / `Closed`, defined by `IsTerminalStatus`.

## 2. Actions

| Action (constant) | Meaning |
| --- | --- |
| `Submit` | Submit (Draft → Submitted) |
| `Start` | Start handling (Submitted → InProgress) |
| `Complete` | Complete (Submitted/InProgress → Completed) |
| `Return` | Return (Submitted/InProgress → Returned); requires a handling comment |
| `Resubmit` | Resubmit (Returned → Submitted); performed by the initiator |
| `Reject` | Reject (Submitted/InProgress → Rejected); requires a handling comment |
| `Cancel` | Cancel (Draft/Submitted/Returned → Cancelled) |
| `Close` | Close / archive (Completed/Rejected/Cancelled → Closed) |
| `CreateDraft` | Creates a draft only; not a transition path |

## 3. Legal transition table (single source of truth)

These 15 transitions are the **single source of truth** for the state machine, defined in
`PortalCollaborationItemTransitions.All`:

| Current status | Action | Target status |
| --- | --- | --- |
| `Draft` | `Submit` | `Submitted` |
| `Submitted` | `Start` | `InProgress` |
| `Submitted` | `Complete` | `Completed` |
| `InProgress` | `Complete` | `Completed` |
| `Submitted` | `Return` | `Returned` |
| `InProgress` | `Return` | `Returned` |
| `Returned` | `Resubmit` | `Submitted` |
| `Submitted` | `Reject` | `Rejected` |
| `InProgress` | `Reject` | `Rejected` |
| `Draft` | `Cancel` | `Cancelled` |
| `Submitted` | `Cancel` | `Cancelled` |
| `Returned` | `Cancel` | `Cancelled` |
| `Completed` | `Close` | `Closed` |
| `Rejected` | `Close` | `Closed` |
| `Cancelled` | `Close` | `Closed` |

- `MapActionToStatus(actionKey)` is derived from this table (each action has exactly one target).
- The SQL `WHERE` predicate of the database write guard is generated by `BuildSqlStatusPredicate` **from the same table**, so
 it cannot drift from the table.

## 4. Enforcement

1. **Explicit server-side gate**: after authorisation (`CanApplyAction`) and before the write, `ApplyAction` calls
 `IsLegalTransition(currentStatus, actionKey)`; an illegal transition is rejected (fail-closed) without leaking internal
 reasons.
2. **Database guard**: the `WHERE` predicate of the SQL `UPDATE` (generated from the transition table) re-validates the current
 status at write time; a zero-row update advances nothing and writes no orphan event.
3. **Authorisation**: `CanApplyAction` decides handling rights by status / action / role, decoupled from transition legality
 (unchanged).
4. **Mandatory comment**: `Return` / `Reject` require a handling comment (`ActionRequiresComment`).
5. **Parent/child constraint**: before entering a terminal state, `HasOpenDescendants` prevents a parent item from being closed
 while its children are not yet terminal.
6. **Time consistency**: `CompletedUtc` / `ClosedUtc` are guaranteed to correspond one-to-one with terminal states by the
 database constraints `CK_..._CompletionUtc` / `CK_..._ClosedUtc` together with the write logic (which syncs by
 `TargetStatus`).

## 5. Every transition writes an event

Every transition that **actually happens** writes one `WorkflowAction` event (`PortalBiz_CollaborationItemEvents`) carrying the
`FromStatus` and `ToStatus` trace; the SQL batch writes events only over the `OUTPUT` set that was actually updated, so a
zero-row update writes no orphan event.

## 6. Out of scope

- The legacy business application `BusinessApplicationDb` (the old sample) has its own state machine and is outside this
 state machine's scope.
- This round adds or removes no status or transition, and changes no business semantics and no UI.
