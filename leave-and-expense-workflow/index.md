# 请假与报销：从填写到出现在待办里

这两件事的形状几乎一样：都是一张表、一次提交、落库，然后在「我的待办」里多出一条待办。放在一起讲一遍。

## 开始之前

- 你已登录门户。两个模块都按当前用户取一次用户记录，取不到就按无权限处理。
- 两个模块都要挂在某个页签上才会出现；找不到页签说明部署方没放出来，找管理员确认。
- 附件都是**可选**的——先确认自己是否真的需要附证明材料或单据；上传本身受附件类型与路径策略约束。

## 提交一条请假

1. 打开承载该模块的页签，在**假别**下拉框里选假别。
2. 填**开始日期**与**结束日期**。
3. 填**天数**。
4. 填**事由**。
5. （可选）上传证明材料。
6. 点**提交**。

成功后：请假记录落表，**「我的待办」里出现一条对应的工作项**，页面下方的列表里也出现这条记录。

## 提交一张报销单

1. 打开承载该模块的页签，在**类别**下拉框里选费用类别。
2. 填**金额**。
3. 填**事由**。
4. （可选）上传单据。
5. 点**提交**。

成功后同样落表，并在「我的待办」里生成一条工作项。

## 两个模块的差别

| | 请假 | 报销 |
| --- | --- | --- |
| 落到的业务表 | `PortalBiz_LeaveRequests` | `PortalBiz_ExpenseReimbursements` |
| 字段 | 假别、起止日期、天数、事由、附件 | 类别、金额、事由、附件 |
| 最容易出问题的一项 | 日期区间（结束早于开始） | 金额格式（非数字） |

除此之外两者同构：**同一套待办写入机制**、都是本人视角的列表、都没有独立编辑页。

## 提交之后

- 你在页面上能看到的只有**自己提交过的**记录 —— 列表按当前用户过滤，没有"查看别人请假/报销"的入口。
- **审批不在这两个模块里**。提交即落表并生成待办，审批发生在待办侧或人工流程里。
- 提交后的记录**不能在这个模块里改**，也没有撤回。
- 想看到待办，去「我的待办」；但要注意那里**只呈现、不办理** —— 它不审批、不改数据，也不回写业务表。

## 提交没成功的时候

- **必填是在提交之后才判的**。两个表单都没有红色必填提示（标记层的必填校验器数量都是 0），填错会在点提交后被服务端拒掉。
- **日期填了却提交失败** —— 格式不被接受，或结束日期早于开始日期；页面上没有日期比较校验器，判定都在服务端。
- **天数填小数或文字失败** —— 需要可解析的数值。
- **金额填了却提交失败** —— 值不是可接受的数字；标记层只把它声明成普通文本框。
- **提交后「我的待办」里没出现** —— 先确认提交是否真的成功：被拒时不落表、也不产生工作项。
- **附件上传失败** —— 受上传类型与路径策略约束，与必填无关。
