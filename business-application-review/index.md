# 审核人操作路径：业务申请怎么批

你是**审核人**（持有 `BusinessApplicationReview` 或 `BusinessApplicationAdmin` 权限）。这篇讲你这一侧：从后台看到一条申请，到批准 / 退回 / 驳回它，以及批完之后去哪查。

申请人那一侧怎么提交、提交后发生了什么，见[业务申请：从提交到办结]({{ site.baseurl }}/business-application-workflow/)；本篇只讲审核台。

## 开始之前

- 入口在后台 **`/Admin/BusinessApplications.aspx`**（页面标题为「业务申请」）。没有该页授权角色就进不去 —— 不是页面坏了。
- 查看与处理共用同一组权限：`BusinessApplicationReview` 或 `BusinessApplicationAdmin` 任一即可。
- 列表只显示**当前状态筛选**下的申请，默认筛选是「已提交」。

## 打开审核页

1. 进入 `/Admin/BusinessApplications.aspx`。
2. 用**状态筛选**下拉框选范围：全部 / 已提交（默认）/ 审核中 / 已退回 / 已批准 / 已驳回 / 已关闭。
3. 点「搜索」按当前筛选重新拉取列表。

每行展示：编号、提交时间（UTC）、申请编号、申请人（用户 ID + 用户名）、申请内容（标题 / 分类 / 摘要 / 正文 / 最近审核）、当前状态，以及审核区（备注框 + 三个按钮）。

## 批一条申请

对每一行，你可以先填一段**审核备注**（最多 1000 字，可留空），然后三选一：

- **批准（Approve）**：申请转到「已批准」（终态）。
- **退回（Return）**：申请转回「已退回」，回到申请人那里补充；申请人重新提交后回到「已提交」。
- **驳回（Reject）**：申请转到「已驳回」（终态）。

点按钮即提交。后台把动作交给数据层的状态机：它负责写申请状态和一条工作流事件，**页面不自己推断状态**。

> 只有这三个动作有效。状态机里还存在「关闭（Close）」等动作，但当前后台页**没有对应的按钮**；强行传别的动作只会得到「不支持的动作」提示，不写任何数据。

## 批完之后

- 每一条成功审核都会记一条**运营审计**（分类 `BusinessModuleCategory`、事件 `BusinessApplicationReviewed`），写清申请编号与动作。
- 同时把结果投影成一条**待办完成事件**：批准 → 已批准、驳回 → 已驳回、退回 → 已评论；对应的「我的待办」项被标为完成。
- 审核人（你）的身份与时间会写进申请记录。

注意一处边界：**待办投影失败不会回滚申请状态**。也就是说，即使待办那一侧没写成功，申请本身该批还是批了。要确认最终结果，看**运营审计页**（`/Admin/OperationAudits.aspx`）和申请记录里的状态，而不是只盯待办。

## 看不到的与做不到的

- **没有独立的审批轨迹界面**：点完之后，过程只落在运营审计与工作流事件里，后台没有一张「谁在什么时候批了什么」的专属页面。
- **没有「撤回 / 认领」按钮**：这两个动作在代码里只有常量、没有接线上界面 —— 审核人侧既不能撤回，也不能认领。
- **「关闭」不在本页**：状态机允许从「已提交 / 审核中」关闭到「已关闭」，但后台审核页只放批准 / 退回 / 驳回，没有关闭按钮。
- 申请人那一侧的**重新提交**界面目前也还没接线（属已知缺口），所以退回后申请人实际怎么重提，要等该缺口补上。
